# Requirement traceability

Each requirement area (from the audit's Section 3.1–3.17 enumeration; exact IDs to be filled once
`CODESENTRA_KICKOFF.md` is committed, F-07) maps to the implementing code, the tests that cover it,
and the **CI gate(s)** that run those tests on every push and PR. The job names in the CI gate
column are the exact `jobs:` in `.github/workflows/ci.yml`; a guard test
(`packages/core/src/traceability.test.ts`) fails CI if any row cites a job that does not exist, if
any CI job is not traced by at least one row, or if any row is missing its code, tests, or CI gate —
so a requirement or a gate cannot be dropped silently.

## Keeping it honest

- The guard test (`packages/core/src/traceability.test.ts`, run in the `test` CI job) parses this
  table and `.github/workflows/ci.yml` and asserts: every CI‑gate token is a real job, every CI
  job is traced by at least one row, and no row is missing its code / tests / CI gate. A dropped
  gate or an invented job name fails CI.
- When `CODESENTRA_KICKOFF.md` is committed (F-07), replace the area descriptions with the spec's
  exact requirement IDs and extend the guard to assert every requirement ID appears at least once.
