# 0006 — Fixture repo layout and expectations

- **Status:** accepted (Phase 0)

## Decisions

- Each fixture repo is `fixtures/repos/<name>/repo/` (the scan input), with
  `fixtures/repos/<name>/expected.json` beside it. `expected.json` sits outside the scanned
  tree because it quotes the planted fake secrets and forbidden claims, which would otherwise
  pollute the scan itself.
- Fixture repos are not pnpm workspace members, so their deliberately vulnerable
  dependencies are never installed into this repo.
- Expectations were confirmed by running each repo in a scratch sandbox (build, tests,
  `npm audit` / `pip-audit`), not just written by hand. `expected.json` records those results.
- `VULNERABLE_DEPENDENCY` expectations are a **superset** check: the named package must be
  flagged, and `mustIncludeAdvisory` must be among the advisories. Advisory databases grow,
  so extra advisories are allowed.
- Planted secrets match gitleaks' `aws-access-token` rule (`AKIA` + 16 chars of `[A-Z2-7]`)
  and deliberately avoid the `…EXAMPLE` allowlist. `.gitleaks.toml` excludes
  `fixtures/repos/` from this repo's own secret scan.
- Zip-style snapshots have no history. A git-history fixture (for co-change and `HOTSPOT`)
  will be generated by a script in Phase 3, because a nested `.git` directory cannot be committed.

## Consequences

The Phase 3 dependency audit needs an offline OSV snapshot for tests. `api.osv.dev` was
unreachable from the development sandbox, and tests must not hit the internet anyway.
