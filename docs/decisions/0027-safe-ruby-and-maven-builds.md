# 0027 — Phase 9: Ruby and Maven builds without code in the download

- **Status:** accepted (Phase 9)

## Context

Under ADR 0026, Ruby and JVM projects were analysed statically but never built. Bundler
evaluates the Gemfile to download gems, and Maven and Gradle run plugins or build scripts
while they resolve dependencies. Either would run code in the one networked step, which
ADR 0016 forbids. Project code may run only offline, in the sandbox. The user chose making
these builds safe for Phase 9.

## Decision

- **Sandbox image.** It adds Ruby 3.4.10 with Bundler 2.6.9 and Java 21 with Maven 3.9.12,
  copied from the official `ruby` and `maven` images. Only `libyaml` was missing from the
  base. `SANDBOX_RUBY_VERSION`, `SANDBOX_JAVA_VERSION` and `SANDBOX_MAVEN_VERSION` are kept
  equal to the Dockerfile by a test.
- **Ruby.** The download never reads the Gemfile.
  - The planner reads `Gemfile.lock` itself (`lockedGems`):
    - every `GEM` section must name rubygems.org;
    - `GIT` sources and other gem servers are refused;
    - `PATH` gems are already in the tree;
    - names and versions must be plain.
  - The download step is our own script, run with `python -I` so nothing in the tree
    loads.
    - It fetches exactly the pinned `.gem` files over HTTPS.
    - It follows redirects only to https `*.rubygems.org`.
    - It checks each file against the lockfile's `CHECKSUMS` (Bundler 2.5+) where present.
      The fetch reason says how many files were checked.
  - Then, offline: `bundle install --local` from that cache, with the project's
    `.bundle/config` set aside and `BUNDLE_VERSION=system`. RSpec or Minitest runs, and
    RuboCop, Sorbet or Steep when the lockfile has them.
  - RSpec failures are matched to tests by `file:line`.
- **Maven.**
  - The download step is our script.
    - Every repository is mirrored to Maven Central, and `-C` enforces checksums.
    - Only Maven's dependency plugin runs, pinned at 3.11.0. `go-offline` downloads
      dependencies and plugins without executing them.
  - Maven resolves the Surefire/Failsafe test providers and the matching JUnit launcher
    only when tests run, so these are fetched explicitly for the versions `go-offline`
    downloaded. Found by running the fixture: without this, tests failed offline.
  - `.mvn/` (JVM options, Maven arguments) is set aside.
  - A POM declaring build extensions, or a `.mvn/extensions.xml`, is refused, because
    Maven loads and runs extensions when it starts.
  - Then, offline: `dependency:resolve`, `package -DskipTests` and `test`. Surefire
    summaries and javac diagnostics are parsed.
- **Failures the sandbox causes are gaps, not the project's failures.** A step can name
  output patterns that turn its failure into "not run, because …":
  - a gem with a native extension (the sandbox has no C compiler);
  - a Gemfile pinning another Ruby;
  - an artifact Maven resolved dynamically that the offline cache lacks;
  - a Java target newer than 21.
- **Gradle stays a gap.** Gradle cannot resolve dependencies without evaluating the build
  script.

## Consequences

- **Residual Maven risk.** A parent POM or BOM fetched from Maven Central can itself
  declare build extensions. The planner sees only the project's own POMs, so such an
  extension, published on Central and chosen by the project, would run during the
  download. Refusing it would mean resolving the parent first, which is a possible follow-up.
  Project code itself never runs during the download.
- **Unverified gem downloads.** Without `CHECKSUMS` in `Gemfile.lock` (Bundler before 2.5),
  gem downloads rely on TLS alone, and the fetch reason says so.
- **Size and speed.** The sandbox image is 1.35 GB, up from 744 MB. The Maven download for
  the Spring Boot fixture is about 275 MB and takes 1–2 minutes.
- **Trivy.** The sandbox image is not Trivy-scanned in CI, as before. It runs untrusted
  code by design, and its toolchains are pinned by tag.
- **Fixture fix.** `rb-notes-api`'s hand-written `Gemfile.lock` (Phase 8) was invalid, and
  Bundler rejected it. It is regenerated by Bundler with checksums.
